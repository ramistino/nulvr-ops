## Source-supported PoC behavior

- The harness spawns a dedicated local Node child capped at 96 MiB V8 old-space, and the child binds only `127.0.0.1` on an ephemeral local port.
- The parent watchdog probes `/live` while a synthetic `/work` request runs. In the deliberately blocked mode, the child burns CPU for a bounded 200–1500 ms, still eventually returns work HTTP 200, and liveness probe failures are reported separately from the p95 latency of successful probes.
- Both request paths and failure simulation are synthetic and loopback-only; the harness does not accept a user-supplied HTTP endpoint, write an ALPS evidence ledger, deploy a service, or create a cloud resource.
- Config keys, allowed scenarios, fixture SHA-256 and a 40-hex `pinnedCommit` *claim* are validated. Results contain tool/config/fixture hashes and explicitly report `OBSERVED`, `productionTarget:false`, `ledgerWrite:false`, and `releaseAuthority:false`.

## Gaps and proposed changes BEFORE operational T2 activation

**G1 — unbounded input read (high in any untrusted runner).** `readFileSync(configPath)` and `readFileSync(config.fixturePath)` fully materialize attacker-selected files *before* checking 4 KiB / 64 KiB limits. The fixture path can read any path accessible to the launching user; a matching user-provided digest is not owner approval. Use independently approved fixture root, no-follow descriptor reads and actual bounded reads before parsing/spawning.

**G2 — watchdog error classification (high for trustworthy metrics).** All fetch exceptions are recorded as `TIMEOUT`, including connection resets/transport errors. Report `TIMEOUT`, `TRANSPORT_ERROR` and `HTTP_NON_200` separately; include them all in the independent liveness-failure count. Test a deliberately closed local socket.

**G3 — fixture identity ≠ workload execution (high for reproducibility).** The harness verifies the fixture hash but does not pass the fixture bytes to the child or derive synthetic workload from its content. Report this explicitly as a fixture provenance marker only, or bind a bounded workload parameter to the fixture in a separately reviewed version. Do not claim workload replay fidelity from current fixture hashing.

**G4 — resource caps remain incomplete.** A 96 MiB V8 old-space flag is *not* an OS RSS cap or CPU quota. Parent deadlines and SIGKILL fallback are useful containment but not a complete memory/process sandbox. Use separately measured RSS/heap/CPU and explicit local host/container limits before real-user workload or remote adapters.

**G5 — provenance/presentation.** Tool SHA-256 is self-reported and `pinnedCommit` is a syntax-validated claim, not independently attested. The existing p95 excludes timed-out probes intentionally; report timeout count alongside it and do not imply percentile coverage of failures. The design blueprint additionally calls for p50/p99, overlapping request identifiers, error-injection scenarios and post-cycle RSS; these have not been implemented.

## Review disposition

**PoC source-bound behavior: OBSERVED / synthetically tested; C4 operational architecture: NOT APPROVED.**

A T2 Architecture Lock may authorize *only* hardening this localhost synthetic facility with bounded reads, distinct error categories, explicit fixture semantics, offline adversarial tests and an independently approved local run recipe. No paid CI, production ALPS probe, remote adapter, new cloud resources or autonomous Orchestrator is covered. For trusted operations require separate GUARD/PROVE validation, measured workload-specific budgets and founder GO.

This is a design/source review, not an independently credentialed PROVE verdict.
